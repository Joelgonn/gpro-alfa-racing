# PIX-010.2 — RELATÓRIO MIGRAÇÃO /v1/payments → /v1/orders

> **Projeto:** GPRO Alfa Racing Brasil | **Branch:** `main` | **PIX-010:** `00e595a` | **PIX-010.1 diagnóstico:** `B — migrar para /v1/orders` | **Data:** 2026-09-19

---

## 1. Diagnóstico da PIX-010.1

PIX-010 implementou Pix via `POST /v1/payments` (`Payments API legacy`) com `APP_USR-` de `Lobo Alfa - Pix → Testes` (`MERCADOPAGO_ENV=sandbox`). Tentativa `POST /v1/payments` com `payer test_user_...` + `19.90` retornou `401 Unauthorized use of live credentials` (cause 7). `POST /users/test_user` com mesmo `APP_USR-` funcionou `201`, provando que `APP_USR-` de Teste é válido para `Orders` mas rejeitado para `Payments` com Pix teste. Documentação: `Checkout Transparente (via Orders API)` recomenda `POST /v1/orders` com `APP_USR` teste, enquanto `Payments API` é `legacy`.

---

## 2. Motivo da migração

Manter `APP_USR-` de `Testes` (regra: não procurar `TEST-`, não trocar credencial por prefixo). `POST /v1/payments` com `APP_USR-` + Pix teste é tratado como `live` pelo gateway (`401`). `POST /v1/orders` com `APP_USR-` de teste é documentado como correto (`test Access Token ... APP_USR`).

## 6. Normalização

**Antes:** `normalizePayment` de `point_of_interaction.transaction_data` (`/v1/payments`).

**Agora:** `normalizeOrder` de `transactions.payments[0]` (`/v1/orders`) + fallback legado:

```ts
normalizeOrder(raw: RawOrderResponse): MercadoPagoPixPayment {
  orderId = String(raw.id) // ORD...
  payment = raw.transactions.payments[0]
  providerPaymentId = String(payment.id) // PAY...
  providerOrderId = orderId
  providerStatus = payment.status
  externalReference = raw.external_reference
  amount = parseFloat(payment.amount) // "19.90" → 19.90
  qrCode = payment.payment_method.qr_code
  ...
}
```

Contrato interno `MercadoPagoPixPayment` estendido com `providerOrderId?: string|null` (`:65`), mantendo `providerPaymentId`, `providerStatus`, `qrCode`, `ticketUrl` compatíveis. `maskRawResponse` agora mascara `transactions.payments[0].payment_method`.

## 9. Webhook

**Antes:** `webhook → data.id (paymentId) → GET /v1/payments/{id}` , `isRelevantEvent` só `payment*` (`order.processed` → `unknown_event`).

**Agora:** suporta ambos:

```ts
isRelevantEvent: payment* || order* (isOrderEvent)
isOrderEvent: order/order.processed

processWebhookEvent:
  if (isOrder) {
    orderMp = await getMercadoPagoOrder(dataId) // GET /v1/orders/{orderId}
    mp = orderMp // já normalizado com providerPaymentId de transactions.payments[0]
    // deriva orderId via external_reference se necessário
  } else {
    mp = await getMercadoPagoPayment(dataId) // GET /v1/payments/{id} (legado, mantido)
  }
```

**Consulta server-to-server nova:** `getMercadoPagoOrder(orderId):304` → `GET /v1/orders/{id}` → `normalizeOrder`.

**Mantido:** `GET /v1/payments/{id}` para compatibilidade (webhook `payment` legado).
