# PIX-004.1 — Correção da inconsistência `tyre_suppliers` em `user_state`

**Data:** 2026-09-17 • **Branch:** `main` • **Projeto remoto:** `cycqigdywekfwwaspsus` (Projeto Alfa Web) • **PIX_ENABLED=false**

## 1. Causa raiz

`npx supabase db lint --linked` conectou corretamente (`Project ref: cycqigdywekfwwaspsus`) mas retornou:

```
ERROR 42703: column "tyre_suppliers" does not exist
```

Função `public.update_user_profile` (criada em `20250917000002_harden_user_state_update.sql`) faz `UPDATE public.user_state SET tyre_suppliers = coalesce(...)` e `INSERT ... tyre_suppliers`. A tabela remota `public.user_state` (verificada via `information_schema.columns` no SQL Editor) contém `vip_status`, `vip_expires_at`, `access_plan`, `access_grant_id`, `car_totals`, `car_characteristic`, mas **não contém** `tyre_suppliers`. A coluna existe apenas no código (`app/lib/db.ts`, `app/lib/tracks.ts`) e no fallback `42703` de `saveUserState`, mas nunca foi criada por migration anterior. A migration `20250918000001_harden_vip_rpc_exposure_part1.sql` (já aplicada) declara explicitamente `NÃO corrige a coluna tyre_suppliers`.

## 2. Arquivos alterados

- **Criado:** `supabase/migrations/20260918000001_add_tyre_suppliers_to_user_state.sql` (único arquivo alterado nesta sprint)
  ```sql
  alter table public.user_state add column if not exists tyre_suppliers jsonb;
  comment on column ... is 'Fornecedores de pneus ...';
  notify pgrst, 'reload schema';
  ```
  Aditivo, `IF NOT EXISTS`, sem `CASCADE`, sem `DROP`, sem dados.

- **Não alterados:** `app/lib/db.ts` (já possui fallback `42703` e `DEFAULT_TYRE_SUPPLIERS`), `supabase/migrations/20250917000002_harden_user_state_update.sql` (mantida como histórico), `supabase/migrations/20250918000001_harden_vip_rpc_exposure_part1.sql` (mantida), `.env.local` (não tocado), `premium_plans` (não tocado), `PIX_ENABLED` (continua `false`).

Verificado: `Get-ChildItem supabase/migrations | Where Name -like "*tyre*"` → 0 antes, 1 após (o novo).

## 3. Migration criada

**Nome:** `20260918000001_add_tyre_suppliers_to_user_state.sql` (posterior a `20250919000003`, ordem garantida por `supabase migration list --linked`: local `20260918000001` pendente, remoto ainda sem ela).
